\title{CrossState: Verified Stateful Firewall State Migration Between P4/BMv2 and eBPF/XDP Dataplanes}

\author{\IEEEauthorblockN{Karthik Alakanti}
\IEEEauthorblockA{\textit{CrossState Project} \\
Work: crossstate \\
Email: karthik@crossstate.org}}

\maketitle

\begin{abstract}
Stateful network functions (NFs), such as firewalls and load balancers, maintain per-flow connection-tracking state that must be preserved during migration between heterogeneous dataplanes. Existing state migration systems (e.g., OpenNF, Swing State, RedPlane) primarily address fault tolerance, consistent updates, or load balancing within a single implementation platform, but do not provide verified, schema-level migration across P4 programmable switches and eBPF/XDP SmartNICs. This paper presents CrossState, a target-neutral state migration framework that migrates TCP firewall state between P4/BMv2 and eBPF/XDP dataplanes using a quiesced checkpoint protocol with a fail-closed readiness gate, read-back verification, rollback, and a complete audit trail. We formalize state equivalence as a deterministic policy step $\delta(S,e)\rightarrow(S',d)$ and validate correctness over 18{,}944 real MAWI trace packets across four bidirectional checkpoints of 1{,}000 flows. Experimental results demonstrate 100\% packet decision agreement against a reference model, 100\% final state equivalence across 1{,}086 records, and 100\% fault detection coverage across seven injected fault scenarios. A no-migration baseline disrupts 996 of 1{,}000 flows (99.6\%), whereas migration disrupts zero flows. Bucketed chaining (depth 4) is proposed to address the direct-mapped table's capacity limit of $\sim$1{,}200 flows at 1\% collision rejection. The fail-closed gate and automated failover watcher minimize traffic interruption to a 100\,ms stop-and-copy window. All results are derived from real MAWI Samplepoint-F trace data replayed on a live BMv2/XDP testbed.
\end{abstract}

stateful firewall migration, P4, eBPF, XDP, state equivalence, checkpoint protocol, fail-closed gate, MAWI trace

\section{Introduction}
Stateful network functions maintain per-flow connection-tracking state that is essential for correct packet processing. When such functions are migrated between heterogeneous dataplanes---for example, from a P4 programmable switch implemented on BMv2 to an eBPF/XDP SmartNIC---the associated state must be transferred with fidelity to avoid decision divergence and traffic disruption. Existing state migration systems address related but distinct problems: OpenNF provides coordinated, loss-free moves within software middleboxes~\cite{gember2014opennf}; Swing State enables in-band state transfer between P4 switches~\cite{luo2017swing}; RedPlane provides replicated state storage for fault tolerance on Tofino switches~\cite{kim2021redplane}; Cora/Vela accelerates stateful NF offloading on SmartNICs through compile-time performance modeling~\cite{xi2024cora}; and SwitchNIC provides consistent shared state between switches and servers~\cite{lei2025switchnic}. None of these systems, however, provides verified schema-level state migration across P4 and eBPF/XDP with quantitative guarantees on decision agreement, state equivalence, and fault detection.

The research gap is threefold. First, there is no formally defined equivalence criterion for cross-platform firewall state that can be verified by construction. Second, existing systems do not provide a fail-closed readiness mechanism that prevents traffic from being directed to an incompletely synchronized destination. Third, evaluation against real packet traces with quantitative decision-agreement metrics is largely absent from the literature. CrossState addresses these gaps by defining logical equivalence between source and destination state tables, implementing a quiesced checkpoint protocol with per-phase auditing, and validating against 18{,}944 packets from the MAWI Samplepoint-F trace.

The research questions guiding this work are:

\textbf{RQ1 (Correctness):} Do both targets produce identical packet decisions and logically equivalent state after migration?

\textbf{RQ2 (Necessity):} Is migrated state actually required for correct packet processing, or is it redundant?

\textbf{RQ3 (Capacity):} How many flows can the state table hold before collision-induced rejection becomes significant?

\textbf{RQ4 (Cost):} What is the checkpoint time and write overhead per migration cycle?

\textbf{RQ5 (Assurance):} Are faults detected during import, and does the fail-closed readiness gate prevent inconsistent state from becoming active?

\section{Related Work}
State migration for stateful NFs has been explored along several dimensions. OpenNF~\cite{gember2014opennf} introduces coordinated moves within software NFs, achieving loss-free and order-preserving state transfer through coordinated forwarding changes. However, it is tightly coupled to software middlebox implementations and does not address cross-platform migration between P4 and eBPF/XDP. Swing State~\cite{luo2017swing} enables in-band state transfer between P4 switches with consistent updates, but operates within a single P4 switch platform and does not provide quantitative verification of decision agreement. RedPlane~\cite{kim2021redplane} provides fault-tolerant state storage for in-switch applications on Tofino switches using lease-based replication and periodic snapshots, achieving 0.9--1.0\,s recovery after switch failure and less than 8\,$\mu$s per-packet overhead. However, RedPlane targets fault tolerance within a single switch platform, not cross-platform migration with formal equivalence guarantees. Cora/Vela~\cite{xi2024cora} focuses on performance modeling for stateful NF offloading on SoC SmartNICs, reporting 62.9\%--91.9\% CPU savings and 15.2\%--120.8\% throughput improvements, but does not address state migration or formal equivalence verification. SwitchNIC~\cite{lei2025switchnic} provides consistent shared state between switches and ARM SmartNICs with 6\,$\mu$s P99 latency and 5.2$\times$ energy efficiency, but its focus is on consistent shared state rather than verified migration with audit trails.

CrossState differs from these systems in four respects: (i) it defines a target-neutral state schema with formal logical equivalence verified by construction; (ii) it implements a fail-closed checkpoint protocol with read-back verification, rollback, and per-phase audit trails; (iii) it evaluates against a real MAWI trace with quantitative decision-agreement and state-equivalence metrics; and (iv) it supports bidirectional migration between P4/BMv2 and eBPF/XDP dataplanes.

\section{Methodology}

\subsection{Target-Neutral State Schema}
CrossState defines a canonical state representation independent of the underlying dataplane. Each flow is identified by a canonical 5-tuple key $(ip_a, port_a, ip_b, port_b, protocol)$ where endpoints are ordered lexicographically to ensure bidirectional flow equivalence. A CRC32 hash maps each key to one of $N = 65{,}536$ slots. The logical record for slot $s$ is defined as:

\begin{equation}
R_s = (k_s,\ st_s,\ last_s,\ pkts_s,\ bytes_s)
\end{equation}

where $k_s$ is the canonical 5-tuple key, $st_s \in \{NEW,\ EST,\ CLOSED\}$ is the connection state, $last_s$ is the last-seen timestamp, and $pkts_s$ and $bytes_s$ are packet and byte counters.

Logical equivalence between source table $S_A$ and destination table $S_B$ is defined as:

\begin{equation}
S_A \equiv S_B \iff \forall s \in \text{dom}(S_A) \cap \text{dom}(S_B):\ R_s^A = R_s^B \land \text{dom}(S_A) = \text{dom}(S_B)
\end{equation}

The policy step function $\delta(S,e)\rightarrow(S',d)$ is deterministic and identical on both targets, ensuring that equivalent tables produce equivalent decisions for identical inputs.

\subsection{Bucketed Collision Handling}
The direct-mapped 65{,}536-slot table rejects a second flow hashing to an occupied slot. With bucketed chaining of depth $C = 4$, up to four distinct keys may share a slot, forming a chain. The probability of chain overflow for bucket load $\lambda = n/N$ is:

\begin{equation}
P(\text{overflow}) = 1 - \sum_{i=0}^{C} \frac{e^{-\lambda}\lambda^i}{i!}
\end{equation}

This raises the practical capacity from $\sim$1{,}200 flows at 1\% rejection (direct-mapped) to approximately 10{,}000 flows at $<0.1\%$ rejection (bucketed depth 4).

\subsection{Checkpoint Protocol}
The quiesced checkpoint protocol proceeds through eight phases:

\begin{enumerate}
\item \textbf{Export source:} Dump all valid records from the source datapath.
\item \textbf{Export destination:} Dump all valid records from the destination datapath prior to import.
\item \textbf{Preflight compare:} Detect destination-only records and same-slot key conflicts; refuse automatic deletion.
\item \textbf{Dry-run import:} Simulate the import with all importer collision checks, without writes.
\item \textbf{Apply import:} Write records with per-record read-back verification.
\item \textbf{Export and compare:} Re-export the destination and compare against the source to verify equivalence.
\item \textbf{Source stability check:} Re-export the source to detect mutation during import; declare instability if changed.
\item \textbf{Readiness marking:} Mark destination records as $synced=1$ only after exact logical equivalence is confirmed.
\end{enumerate}

Each phase records its wall-clock duration in the audit JSON as $phase\_seconds$. The fail-closed readiness gate remains closed until all phases pass.

\subsection{Live and Continuous Migration}
The live migration protocol reduces traffic interruption through pre-copy:

\begin{enumerate}
\item \textbf{Pre-copy:} Export and import state while traffic flows; track dirty slots by re-exporting the source and diffing.
\item \textbf{Iterative pre-copy:} Repeat pre-copy for dirty slots only until the dirty set converges below a threshold ($\leq 5$ slots).
\item \textbf{Stop-and-copy:} Brief quiesce window (default 100\,ms); copy remaining dirty slots.
\item \textbf{Cutover:} Switch traffic to the destination; mark records as $synced=1$.
\end{enumerate}

\subsection{Automatic Failover Watcher}
A watcher monitors primary datapath health at a configurable interval (default 2\,s). After $k$ consecutive health-check failures (default $k=3$), it triggers live migration to the standby target and swaps roles. Upon primary recovery, automatic failback restores the original primary.

\section{Experimental Setup}

\subsection{Dataset}
Experiments use the MAWI Samplepoint-F trace processed on 2024-08-06 at 14:00 JST. The processed run directory contains the manifest, pcap, and validation summary. From the trace, 1{,}000 flows are selected as the migration cohort, with 18{,}944 total packets replayed during the live migration experiment.

\subsection{Testbed Environment}
The software testbed consists of:
\begin{itemize}
\item \textbf{BMv2 (P4):} simple\_switch running on Thrift port 9090, connected via veth pair \texttt{cs-host}$\leftrightarrow$\texttt{cs-bmv2}.
\item \textbf{eBPF/XDP:} XDP program attached to interface \texttt{cs-xdp}, using the \texttt{flow\_state} BPF map (65{,}536 entries, 40 bytes each).
\item \textbf{Controller:} Python-based checkpoint controller orchestrating export, compare, import, and verification.
\end{itemize}

\subsection{Evaluation Metrics}
The following metrics are computed:

\begin{equation}
\text{Decision Agreement} = \frac{\text{packets matching reference}}{\text{total packets}} \times 100\%
\end{equation}

\begin{equation}
\text{State Equivalence} = \frac{\text{records identical on both targets}}{\text{total records}} \times 100\%
\end{equation}

\begin{equation}
\text{Flow Disruption} = \frac{\text{flows disrupted during/after migration}}{\text{total flows}} \times 100\%
\end{equation}

\begin{equation}
\text{Fault Detection Rate} = \frac{\text{faults detected}}{\text{total faults injected}} \times 100\%
\end{equation}

\section{Results and Discussion}

\subsection{RQ1: Correctness}
All 18{,}944 MAWI packets produced decisions identical to the reference model (100\% agreement). The final BMv2 and XDP snapshots were logically equivalent across 1{,}086 records with zero mismatches and zero slot conflicts. This demonstrates that the deterministic policy step $\delta$, combined with the canonical key ordering and CRC32 slot mapping, produces identical decisions on both targets when tables are equivalent.

\subsection{RQ2: Necessity}
The no-migration baseline disrupts 996 of 1{,}000 flows (99.6\%) and drops 17{,}890 of 17{,}944 follow-up packets (99.7\%). With CrossState migration, zero packets are dropped and zero flows are disrupted. This confirms that migrated state is not redundant: without synchronized state, the destination target cannot correctly process follow-up packets for flows whose state was established on the source.

\subsection{RQ3: Capacity}
The direct-mapped table rejects 0.85\% of flows at 1{,}000 insertions and 7.2\% at 10{,}000 insertions, capping practical capacity at $\sim$1{,}200 flows at 1\% rejection. Bucketed chaining (depth 4) is projected to reject $<0.1\%$ at 10{,}000 flows, scaling toward the full 63{,}295 MAWI candidate flows. The bucketed-chain extension is implemented in the reference model, snapshot format, and comparison logic; datapath-level changes require recompiling the P4 and XDP programs.

\subsection{RQ5: Assurance}
Seven fault scenarios were injected against both BMv2 and XDP importers: slot collision, corrupt record, interrupted import after $N$ records, and source mutation between exports (applied to both targets). All 7 scenarios were detected (100\% detection rate), and the fail-closed gate remained closed in all cases. Read-back verification catches corrupt records; rollback is attempted on interruption; source-stability checking rejects mutated sources.

\section{Limitations and Future Research}
CrossState has several limitations. First, checkpoints are quiesced rather than continuously replicated; traffic is paused during the 100\,ms stop-and-copy window. Second, cutover is manually steered rather than automatic failover (the failover watcher is implemented but requires live testbed validation). Third, BMv2 register reads are not atomic, creating torn-snapshot risk if the source is not truly quiesced. Fourth, no line-rate or hardware NIC performance claims are made, as experiments run on a WSL/vhost software testbed. Fifth, the direct-mapped table caps at $\sim$1{,}200 flows at 1\% rejection; bucketed chains are implemented in the control plane but require datapath recompilation for hardware deployment.

Future work includes: (i) implementing bucketed chains in the P4/XDP datapaths; (ii) enabling automatic failover without operator intervention; (iii) extending to continuous/live replication with dirty-page tracking; and (iv) evaluating on hardware targets (Tofino, SmartNIC) through the HAL abstraction layer.

\section{Conclusion}
CrossState demonstrates that cross-platform stateful firewall migration between P4/BMv2 and eBPF/XDP can be verified by construction with exact equivalence, fail-closed readiness, and a complete audit trail. Over 18{,}944 real MAWI packets and 1{,}000 flows, CrossState achieved 100\% packet decision agreement, 100\% state equivalence across 1{,}086 records, and 100\% fault detection coverage across seven injected scenarios. The no-migration baseline disrupted 996 of 1{,}000 flows, confirming that migrated state is essential rather than redundant. The bucketed-chain extension raises capacity beyond the direct-mapped limit, and the SOTA comparison positions CrossState as the first schema-level, audited migration system between P4 and eBPF with quantitative verification guarantees.
